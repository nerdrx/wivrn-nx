# NX ASTC: quality follows the frame budget

The native full-eye path now has nine quality rungs. q0–q6 retain the existing ASTC 8×8 representation. q7 uses 6×6 blocks at q6 precision; q8 uses 4×4 blocks with full 8-bit RGB endpoints and one three-bit weight per pixel. Every physical block remains 128 bits. Smaller blocks represent more local colour variation; they do not increase output resolution or require a separate reconstruction shader.

The existing bitrate slider supplies a per-eye, per-frame byte budget. The controller measures the final independently packed raw/LZ4/Zstd packet. It prefers the smallest recently measured footprint that fits with 5% headroom. Unmeasured upgrades require 30% spare budget and progress one rung at a time. Over-budget packets immediately influence downshifting; a failed smaller-footprint estimate cannot hide behind an older low moving average. Measurements expire after 30 other frames so changing scenes can be reconsidered. This is adaptive estimation, not a guarantee that every individual packet stays below its budget. A newly probed footprint can overshoot before the controller has measured it. An over-budget 6×6/4×4 packet is withheld rather than sent as a network burst, and the next frame downshifts. That costs a fresh update on a failed probe. Legacy 8×8 rungs retain their existing 10% controller tolerance.

8×8 retains legacy packet versions 1/2. Version 3 records a 4×4 or 6×6 footprint in header byte 6 and validates the corresponding exact block length. The headset uses matching Vulkan ASTC formats. Format-specific image pools are allocated on first use and retained, preventing destruction of textures still held by presentation. The shared CPU decompression buffer is sized for 4×4; each packet decodes into its own exact-length prefix. Transfer fences and image ownership remain enforced.

## Optional colour smoothing

On Android, `debug.wivrn.nx.peripheral_smooth=6` enables a small colour-only softener in the existing presentation shader. Set it to `0` to disable. The default remains off. Mode 6 does not depend on PLANAR centre settings and excludes compact-centre and alpha paths. It reads two clamped diagonal samples at ±3 source pixels, blends their colour toward the current sample, removes the BT.709 luma component of that change, and limits the change to the RGB gamut. Brightness detail is preserved in the sampled encoded domain; the existing colour conversion still runs once afterwards. It adds two texture samples, not another GPU pass or temporal history. It cannot remove brightness-only block artefacts or replace missing colour detail.

## Validation and limits

Focused packet, decompression-prefix, and rate-controller checks live in `common/test_nxastc_packet.cpp`, `tests/nxastc_packet_decode_test.cpp`, and `tests/astc_rate_control_test.cpp`. Generated 6×6 interpolation tables use the standard ASTC integer interpolation coefficients. Host and Android shader compilation must pass before deployment.

Smaller blocks increase raw block storage, upload traffic, and potentially sampling/decompression cost. Relative to 8×8, 6×6 uses about 1.78× and 4×4 4× as many blocks before independent packing. The controller responds to packet bytes; it does not prove headset thermal headroom, latency, or perceived quality. Short live observations and offline crops must be reported separately. Encoder packet means include attempted expansion probes; the accompanying expansion-drop count identifies packets withheld before transmission. Neither synthetic timings nor refresh-target offsets prove motion-to-photon latency.
